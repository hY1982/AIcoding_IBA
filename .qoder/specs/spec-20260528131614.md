# Module 1.3 — 赛制实体（formats）实现计划

## Context

根据 `basketball-match-platform-specs.md` 和 `basketball-match-platform-blueprint.md`，Module 1.3 是 Phase 1（数据层）的第三个模块。在 Module 1.1（用户/球员实体）和 Module 1.2（场地实体）完成后，需要定义赛制（format）实体，为后续比赛意向（intentions）和匹配引擎提供赛制数据支撑。

赛制实体是一个独立表（无外部外键依赖），包含 3v3/4v4/5v5 短赛等初始种子数据，是匹配算法中判断人数要求的核心依据。

## 已探索的现有模式

- **实体定义**：`server/src/modules/venues/entities/venue.entity.ts` — 使用 `@Entity('table_name')`、`@PrimaryGeneratedColumn('increment', { type: 'bigint' })`、`@Column({ name: 'snake_case' })`、`@CreateDateColumn`
- **实体测试**：`server/src/modules/venues/entities/venue.entity.spec.ts` — 使用真实 PostgreSQL `DataSource`，`synchronize: true`，`information_schema` 验证表结构，`TRUNCATE TABLE ... CASCADE` 清理
- **迁移文件**：`server/src/migrations/1716740000002-CreateVenueTables.ts` — 原始 SQL，先 ENUM → 表 → 索引 → FK，`down()` 严格反向 + `IF EXISTS`
- **模块注册**：`server/src/app.module.ts` 导入各 Module，`venues.module.ts` 使用 `TypeOrmModule.forFeature([...])`
- **共享类型**：`shared/types/venue.ts` — `const ARRAY = [...] as const` + `type Type = (typeof ARRAY)[number]` 模式
- **Jest 配置**：覆盖率阈值 80%，`moduleNameMapper` 支持 `@shared/*` 等路径别名

### 详细设计

#### 1. 共享类型 `shared/types/format.ts`

```typescript
export const FORMAT_TYPES = ['short', 'long'] as const;
export type FormatType = (typeof FORMAT_TYPES)[number];
export const FORMAT_TYPE_LABELS: Record<FormatType, string> = {
  short: '短赛',
  long: '长赛',
};

export interface Format {
  id: number;
  name: string;
  formatType: FormatType;
  teamSize: number;
  teamCountMin: number;
  teamCountMax: number;
  winCondition?: string;
  /** 预计总占用时长（包含热身与间歇），单位：小时 */
  durationHours?: number;
  description?: string;
  isActive: boolean;
  createdAt: string;
}
```

#### 2. 实体 `server/src/modules/formats/entities/format.entity.ts`

根据 blueprint 的 `formats` 表结构：

| 字段 | TypeORM 装饰器 | 约束 |
|------|---------------|------|
| `id` | `@PrimaryGeneratedColumn('increment', { type: 'bigint' })` | PK |
| `name` | `@Column({ type: 'varchar', length: 50, nullable: false })` | NOT NULL |
| `formatType` | `@Column({ name: 'format_type', type: 'enum', enum: FORMAT_TYPES, nullable: false })` | NOT NULL |
| `teamSize` | `@Column({ name: 'team_size', type: 'int', nullable: false })` | NOT NULL |
| `teamCountMin` | `@Column({ name: 'team_count_min', type: 'int', nullable: false })` | NOT NULL |
| `teamCountMax` | `@Column({ name: 'team_count_max', type: 'int', nullable: false })` | NOT NULL |
| `winCondition` | `@Column({ name: 'win_condition', type: 'varchar', length: 100, nullable: true })` | NULL |
| `durationHours` | `@Column({ name: 'duration_hours', type: 'decimal', precision: 3, scale: 1, nullable: true })` | NULL，单位：小时，精度0.1h（6分钟） |
| `description` | `@Column({ type: 'text', nullable: true })` | NULL |
| `isActive` | `@Column({ name: 'is_active', type: 'boolean', nullable: true, default: true })` | DEFAULT true；软删除标记，查询业务需显式筛选 |
| `createdAt` | `@CreateDateColumn({ name: 'created_at' })` | auto |

注意：formats 表无外键关系，是独立表。

#### 4. 测试设计（TDD — 先写测试）

`format.entity.spec.ts` 包含两个 describe 块：

**`describe('table structure')`**
- `should create formats table with correct columns` — 验证所有列存在
- `should have id as bigint primary key` — 验证 id 类型
- `should have name as varchar(50) non-nullable` — 验证 name 约束
- `should have format_type as enum non-nullable` — 验证 format_type 是 enum 类型
- `should have team_size, team_count_min, team_count_max as int non-nullable` — 验证三个 int 字段
- `should have duration_hours as decimal(3,1)` — 验证精度
- `should have is_active default to true` — 验证默认值
- `should have created_at as timestamptz` — 验证时间戳类型

**`describe('entity creation')`**
- `should create a format with all fields` — 完整字段 CRUD
- `should reject invalid format_type` — 非法 enum 值应抛错
- `should default is_active to true` — 默认值验证
- `should allow optional fields to be null` — winCondition/durationHours/description 可为 NULL
- `should reject team_count_max < team_count_min via database CHECK constraint` — 通过 `repository.query()` 直接执行违反 `CHK_formats_team_counts` 约束的 INSERT，断言数据库抛出包含 `CHK_formats_team_counts` 的错误

#### 5. 迁移文件设计

**`1716740000003-CreateFormatTable.ts`**

```typescript
export class CreateFormatTable1716740000003 implements MigrationInterface {
  name = 'CreateFormatTable1716740000003';

  public async up(queryRunner: QueryRunner): Promise<void> {
    // 1. ENUM type
    await queryRunner.query(
      `CREATE TYPE "public"."formats_format_type_enum" AS ENUM('short','long')`,
    );
    // 2. Create table
    await queryRunner.query(
      `CREATE TABLE "formats" (
        "id" BIGSERIAL NOT NULL,
        "name" character varying(50) NOT NULL,
        "format_type" "public"."formats_format_type_enum" NOT NULL,
        "team_size" integer NOT NULL,
        "team_count_min" integer NOT NULL,
        "team_count_max" integer NOT NULL,
        "win_condition" character varying(100),
        "duration_hours" numeric(3,1),
        "description" text,
        "is_active" boolean DEFAULT true,
        "created_at" TIMESTAMPTZ NOT NULL DEFAULT now(),
        CONSTRAINT "PK_formats" PRIMARY KEY ("id"),
        CONSTRAINT "CHK_formats_team_counts" CHECK ("team_count_max" >= "team_count_min")
      )`,
    );
  }

  public async down(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.query(`DROP TABLE IF EXISTS "formats"`);
    await queryRunner.query(`DROP TYPE IF EXISTS "public"."formats_format_type_enum"`);
  }
}
```

**`1716740000004-SeedFormats.ts`**

```typescript
export class SeedFormats1716740000004 implements MigrationInterface {
  name = 'SeedFormats1716740000004';

  public async up(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.query(

    );
  }

  public async down(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.query(
      `DELETE FROM "formats" WHERE "name" IN ('3v3短赛','4v4短赛','5v5短赛')`,
    );
  }
}
```

> **架构决策记录（ADR）**：`format_type` 使用 PostgreSQL ENUM 类型而非 varchar + CHECK，以换取数据完整性与查询性能。未来新增枚举值（如 'training'、'tournament'）需通过新的迁移脚本执行 `ALTER TYPE ... ADD VALUE`。此权衡在 `docs/design/adr-001-format-type-enum.md` 中记录（后续补充）。
```

4. **迁移执行**：`cd server && npm run migration:run` — 成功创建 formats 表并插入种子数据
5. **迁移回滚**：`cd server && npm run typeorm -- migration:revert -d src/data-source.ts`（执行两次，先回滚 SeedFormats，再回滚 CreateFormatTable）— 验证 `down()` 正常
6. **重新迁移**：再次 `npm run migration:run` — 验证幂等性
7. **种子数据验证**：迁移执行后查询数据库，`SELECT * FROM formats` 应返回 3 条记录（3v3/4v4/5v5 短赛）
