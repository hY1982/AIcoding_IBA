# Module 1.5 — 比赛与群聊实体（matches + match_players + match_teams + match_messages）

## Context

根据 `basketball-match-platform-specs.md` 中 Module 1.5 的要求，本项目需要定义比赛（matches）、比赛球员关联（match_players）、比赛队伍（match_teams）、群聊消息（match_messages）四个核心实体。这些实体是匹配引擎产出的核心数据载体，支撑比赛确认、队伍分配、群聊通信等后续业务流程。

当前项目已完成 Module 1.1~1.4（用户/球员/场地/赛制/意向实体），建立了完整的 TypeORM + PostgreSQL + TDD 开发范式。Module 1.5 需要在此基础上，严格遵循已有模式完成比赛相关实体的定义、关系映射、迁移和测试。

## 已有模式总结（从探索结果提炼）

1. **实体文件位置**: `server/src/modules/{module}/entities/{entity}.entity.ts`
2. **测试文件位置**: `server/src/modules/{module}/entities/{entity}.entity.spec.ts`
3. **迁移文件位置**: `server/src/migrations/{timestamp}-{PascalCase}.ts`，时间戳递增
4. **共享类型位置**: `shared/types/match.ts`（新增）
5. **模块注册**: 在 `app.module.ts` 中导入新模块
6. **测试模式**: DataSource + synchronize: true + information_schema 验证 + 实体操作验证
7. **ENUM 定义**: 在 `shared/types/` 中用 `as const` 数组定义，实体中引用
8. **迁移模式**: 原生 SQL 建表 + ALTER TABLE 加外键 + 幂等 down 方法

### Phase 2: 编写实现代码（TDD 绿阶段）

**关键实施约束（来自评审反馈）**：

1. **ENUM 创建幂等性**: 迁移文件中所有 `CREATE TYPE` 语句必须使用 `DO $$ BEGIN ... EXCEPTION WHEN duplicate_object THEN null; END $$;` 包装
2. **懒加载配置**: Match 实体中的 `@OneToMany` 关系必须显式设置 `{ lazy: true }`，防止意外触发关联加载和循环序列化
3. **外键删除策略**: `intentions.match_id` 和 `venue_time_slots.match_id` 补充外键时使用 `ON DELETE SET NULL`
4. **confirmed_players 维护**: 实体中不提供直接 setter，仅通过服务层事务方法更新（Module 2.7 实现）

// 比赛状态
export const MATCH_STATUSES = [
  'pending_confirmation',
  'confirmed',
  'in_progress',
  'completed',
  'cancelled',
  'failed',
] as const;
export type MatchStatus = (typeof MATCH_STATUSES)[number];

// 比赛球员参赛状态
export const MATCH_PLAYER_STATUSES = [
  'invited',
  'confirmed',
  'declined',
  'no_show',
] as const;
export type MatchPlayerStatus = (typeof MATCH_PLAYER_STATUSES)[number];

// 消息类型
export const MESSAGE_TYPES = ['text', 'image', 'system'] as const;

/**
 * 比赛状态机 — 定义合法的状态流转路径。
 * 为 Module 2.7（比赛确认服务）提供状态流转校验依据。
 *
 * 状态流转规则：
 * - pending_confirmation: 匹配成功，等待球员确认参赛
 * - confirmed: 足够人数确认，比赛正式确认

 * - completed: 比赛结束，进入反馈阶段

 * - failed: 匹配失败（确认人数不足）
 */
export const MATCH_STATUS_TRANSITIONS: Record<
  MatchStatus,
  MatchStatus[]
> = {
  pending_confirmation: ['confirmed', 'cancelled', 'failed'],
  confirmed: ['in_progress', 'cancelled'],
  in_progress: ['completed', 'cancelled'],
  completed: [],
  cancelled: [],
  failed: [],
};

表名: `matches`

|------|---------------|------|
| `id` | `@PrimaryGeneratedColumn('increment', { type: 'bigint' })` | 主键 |
| `venueId` | `@Column({ name: 'venue_id', type: 'bigint', nullable: false })` + `@ManyToOne(() => Venue)` | 关联场地 |

| `status` | `@Column({ type: 'enum', enum: MATCH_STATUSES, nullable: false, default: 'pending_confirmation' })` | 比赛状态 |
| `teamCount` | `@Column({ name: 'team_count', type: 'int', nullable: false })` | 队伍数 |
| `playersPerTeam` | `@Column({ name: 'players_per_team', type: 'int', nullable: false })` | 每队人数 |
| `totalPlayers` | `@Column({ name: 'total_players', type: 'int', nullable: false })` | 总人数 |
| `confirmedPlayers` | `@Column({ name: 'confirmed_players', type: 'int', nullable: false, default: 0 })` | 已确认人数 |
| `depositAmount` | `@Column({ name: 'deposit_amount', type: 'decimal', precision: 10, scale: 2, nullable: false })` | 保证金 |
| `groupChatId` | `@Column({ name: 'group_chat_id', type: 'varchar', length: 100, nullable: true })` | 群聊房间ID |
| `regionCode` | `@Column({ name: 'region_code', type: 'varchar', length: 20, nullable: true })` | 地区编码 |
| `createdAt` | `@CreateDateColumn({ name: 'created_at' })` | 创建时间 |
| `updatedAt` | `@UpdateDateColumn({ name: 'updated_at' })` | 更新时间 |
| `matchPlayers` | `@OneToMany(() => MatchPlayer, (mp) => mp.match, { cascade: true, lazy: true })` | 关联球员（懒加载） |
| `matchTeams` | `@OneToMany(() => MatchTeam, (mt) => mt.match, { cascade: true, lazy: true })` | 关联队伍（懒加载） |
| `messages` | `@OneToMany(() => MatchMessage, (msg) => msg.match, { cascade: true, lazy: true })` | 关联消息（懒加载） |

索引: `@Index(['status'])`, `@Index(['startTime'])`, `@Index(['venueId', 'startTime'])`, `@Index(['regionCode'])`

关系设计:
- `venue` → `@ManyToOne(() => Venue, { onDelete: 'NO ACTION' })` — 场地删除时不级联（保护比赛历史）
- `format` → `@ManyToOne(() => Format, { onDelete: 'NO ACTION' })` — 赛制删除时不级联

**设计注释 — `confirmedPlayers` 字段维护策略**:
此字段为反范化聚合字段，存储已确认参赛的球员数量。其值必须与 `match_players` 表中 `is_confirmed = true` 的记录数保持一致。

维护策略（由 Module 2.7 MatchService 实现）：
1. 球员确认参赛时：通过事务同时更新 `match_players.is_confirmed = true` 和 `matches.confirmed_players += 1`
2. 球员取消确认时：通过事务同时更新 `match_players.is_confirmed = false` 和 `matches.confirmed_players -= 1`
3. 系统确认比赛时：校验 `confirmed_players >= format.team_size * format.team_count_min`
4. 禁止直接修改 `confirmed_players` 字段（不设 setter，仅通过服务层方法更新）

**设计注释 — `group_chat_id` 字段**:
此字段由外部群聊服务（如 Socket.io Room ID）在比赛状态流转为 `confirmed` 时创建并回填。
生成逻辑：Module 2.7 MatchConfirmationService 在比赛确认成功后，生成唯一 room ID（如 `match_${matchId}_${timestamp}`）并写入此字段。
此字段不可由用户直接设置。
