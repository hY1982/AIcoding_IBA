# Module 2.1 — 基础能力值计算服务（AbilityCalculationService）实现计划

## Context

根据 `basketball-match-platform-specs.md` 中 Module 2.1 的要求，本项目需要实现一个 AbilityCalculationService，用于根据球员的生理和篮球属性计算基础能力值。该服务是后续匹配引擎（Module 2.6）的核心依赖——匹配算法需要基于球员的综合能力值（baseAbilityScore + matchAdjustValue）进行分组。

**本次计划已根据业务需求变更进行调整：MVP取消位置适配调整机制，P1阶段引入位置权重系统。**

当前项目状态：
- Phase 0（基础设施）和 Phase 1（数据层 + Migrations）已全部完成
- `Player` 实体已包含 `baseAbilityScore`、`matchAdjustValue`、`totalAbilityScore`（生成列）字段
- `SystemParam` 实体和种子数据已就绪，包含 `base_ability_weights` 初始配置（MVP版本不含position_fit）
- `shared/types/system.ts` 已定义 `BaseAbilityWeights` 接口和类型守卫 `isBaseAbilityWeights`
- `PlayersModule` 当前仅导出 TypeOrmModule，无 Service/Controller

## 设计决策

### 1. 百分位数据集设计

MVP 使用预设的固定百分位数据集（模拟中国男性/女性体质监测公开数据）。数据集按性别分离，每个指标提供一组 `(value, percentile)` 数据点。百分位计算采用**线性插值法**：

```
给定 value，找到相邻的两个数据点 (v1, p1) 和 (v2, p2)
percentile = p1 + (value - v1) * (p2 - p1) / (v2 - v1)
```

边界处理：
- value < 最小数据点 → 返回 0
- value > 最大数据点 → 返回 100
- 精确匹配数据点 → 返回对应百分位

数据集文件 `percentile-datasets.ts` 包含：
- `MalePercentileDataset` / `FemalePercentileDataset`
- 每个指标（height, weight, wingspan, standingReach, jumpingReach, basketballAge, age）的排序数据点数组

### 2. MVP取消位置适配度计算

**根据业务需求变更，MVP阶段移除位置适配度（position_fit）计算。**

原因：
- 原 `position_fit` 机制（按申报位置数量给基础分+身高适配度微调）主观性过强
- MVP阶段采用统一的身体属性权重计算基础能力值，简化匹配逻辑
- 位置信息仍由球员申报并存储（`player_positions`表），但仅用于P1阶段的位置权重系统

MVP阶段 `base_ability_weights` 权重分配（不含position_fit，总权重仍为1.0）：
- height: 0.20（原0.15）
- weight: 0.10（原0.05）
- wingspan: 0.15（原0.10）
- standingReach: 0.15（原0.10）
- jumpingReach: 0.20（原0.15）
- basketballAge: 0.15（原0.20）
- age: 0.05（不变）

### 3. P1位置权重系统（预留扩展）

P1阶段将引入位置权重系统，设计要点：
- 不同位置(PG/SG/SF/PF/C)对身体属性采用差异化权重
- 后卫(PG/SG)：身高权重较低，速度、起跳高度权重较高
- 中锋(C)：身高权重较高，其他属性权重相对较低
- 前锋(SF/PF)：平衡型权重配置
- 权重独立存储于 `system_params` 表（如 `position_ability_weights` 键）
- 多位置球员按各位置权重分别计算能力值
- 匹配算法基于具体位置进行匹配

**MVP阶段不在代码中实现位置权重计算，但Service架构预留扩展接口。**

### 4. 服务架构与权重提供者抽象（P1建议）

```
AbilityWeightsProvider (接口)
├── SystemParamWeightsProvider — 从数据库 system_params 读取
└── DefaultWeightsProvider — 返回硬编码默认值

AbilityCalculationService
├── constructor(weightsProvider: AbilityWeightsProvider)
├── calculateBaseAbility(player: PlayerAttributes): number
│   ├── 通过 weightsProvider 获取权重
│   ├── 校验权重和是否为 1.0（安全网）
│   ├── 校验失败 → 回退到 DefaultWeightsProvider
│   ├── 对每个指标调用 getPercentile()
│   └── 加权求和，返回 0-100 的得分
├── getPercentile(value, gender, metric): number
│   └── 从 percentile-datasets.ts 查询并插值
└── getDefaultWeights(): BaseAbilityWeights
    └── MVP默认权重（不含position_fit，和为1.0）
```

**P1建议：采用 AbilityWeightsProvider 接口解耦数据库依赖**

理由：
- 提升可测试性：单元测试可注入 MockProvider，无需连接数据库
- 提升架构清晰度：权重获取逻辑与计算逻辑分离
- 便于扩展：P1阶段新增 `PositionWeightsProvider` 时无需改动计算服务

MVP实现策略（兼顾简洁与可扩展）：
- 定义 `AbilityWeightsProvider` 接口（`getWeights(): BaseAbilityWeights`）
- 提供 `DefaultWeightsProvider` 实现（硬编码MVP权重）
- 提供 `SystemParamWeightsProvider` 实现（从数据库读取，读取失败时委托给 DefaultWeightsProvider）
- `AbilityCalculationService` 构造函数注入 `AbilityWeightsProvider`，默认使用 `SystemParamWeightsProvider`
- **权重校验安全网**：`calculateBaseAbility()` 在计算前校验权重和是否为 1.0（允许 ±0.01 浮点误差），校验失败则回退到 `DefaultWeightsProvider`

**移除的方法**：`calculatePositionFit()` — MVP不实现位置适配度计算

### 5. 权重获取策略

Service 支持两种权重获取方式：
1. **运行时从数据库读取**（通过 `SystemParamWeightsProvider`）—— 支持管理员动态调整权重
2. **fallback 到默认值**（通过 `DefaultWeightsProvider`）—— 保证服务在数据库不可用时仍能工作

考虑到 Module 2.1 的依赖顺序（Module 1.1 完成后即可开始），SystemParamService 可能尚未实现。因此采用以下策略：
- `SystemParamWeightsProvider` 尝试从数据库读取 `base_ability_weights`
- 若读取失败、不存在或结构不合法，委托给 `DefaultWeightsProvider`
- `AbilityCalculationService` 在计算前执行**权重和校验**（安全网），校验失败同样回退到默认值
- 后续 Module 2.3（PlayerService）中再集成完整的 SystemParam 动态读取

### 6. 可空字段处理

Player 实体中 `weight`、`wingspan`、`standingReach`、`jumpingReach` 均为可空字段。计算策略：
- 字段为 `null` 时，使用**该性别该指标的中位数**作为默认值，百分位打分为 50
- 这样既不惩罚也不奖励缺失数据的球员，保持公平性

## 需要创建的文件

### 1. 百分位数据集

**文件**: `server/src/modules/players/data/percentile-datasets.ts`

内容：
- `PercentileDataPoint` 接口：`{ value: number; percentile: number }`
- `PercentileDataset` 接口：按指标名映射到 `PercentileDataPoint[]`
- `MALE_PERCENTILE_DATASET`: 男性各指标数据
- `FEMALE_PERCENTILE_DATASET`: 女性各指标数据
- `getDataset(gender: Gender): PercentileDataset` 辅助函数

**数据来源说明（P2重要建议）**：

当前数据集基于中国国民体质监测公开数据**合理估算**，属于**已知假设（Known Assumption）**，存在以下局限：
- 数据来源为一般人群体质监测，非篮球专项人群，可能存在系统性偏差
- 篮球运动员的身体素质分布（如臂展、起跳摸高）与普通人群差异显著
- 女性数据为基于男性数据的性别差异调整，未使用独立的女性篮球运动员样本
- 年龄分布假设为16-40岁，可能未覆盖所有目标用户群体

**未来校准规划**：
- MVP上线后收集真实用户数据，定期（每季度）分析各指标的分布情况
- 当样本量达到统计显著性（每个性别≥1000人）时，用真实数据替换估算数据
- 校准过程应通过A/B测试验证：对比新旧数据集对匹配成功率的影响
- 数据集版本化管理，保留历史版本以便回滚

具体数据点（估算值）：
- 男性身高：160cm(5%) → 170cm(25%) → 175cm(50%) → 180cm(75%) → 190cm(95%)
- 男性体重：55kg(5%) → 65kg(25%) → 72kg(50%) → 80kg(75%) → 95kg(95%)
- 男性臂展：165cm(5%) → 175cm(25%) → 180cm(50%) → 188cm(75%) → 198cm(95%)
- 男性站立摸高：210cm(5%) → 220cm(25%) → 228cm(50%) → 235cm(75%) → 245cm(95%)
- 男性起跳摸高：270cm(5%) → 285cm(25%) → 300cm(50%) → 315cm(75%) → 330cm(95%)
- 男性球龄：0年(5%) → 1年(25%) → 3年(50%) → 6年(75%) → 12年(95%)
- 男性年龄：16岁(5%) → 20岁(25%) → 26岁(50%) → 32岁(75%) → 40岁(95%)
- 女性对应数据按性别差异调整

## 风险与注意事项

1. **百分位数据集的合理性（P2）**：MVP 使用估算数据，后续需根据真实用户数据校准。数据集设计为可替换，不影响服务接口。务必在数据集文件头部添加详细的数据来源说明和校准规划注释。
2. **可空字段默认值策略**：使用 50 分（中位数）作为默认值，避免缺失数据的球员被过度惩罚或奖励。
3. **位置适配度取消的影响**：MVP阶段匹配仅基于综合能力值，不区分位置差异。P1阶段引入位置权重系统后需同步更新匹配引擎。
4. **SystemParam 依赖**：Module 2.1 不强制依赖 SystemParamService（可能未实现），使用默认值 fallback 策略。通过 `AbilityWeightsProvider` 接口解耦，便于测试和扩展。
5. **P1扩展预留**：Service架构应保持可扩展性，便于后续添加 `calculatePositionAbility()` 等方法。
6. **权重和校验（P0安全网）**：`calculateBaseAbility()` 必须在计算前校验权重和是否为 1.0（±0.01 浮点误差），校验失败立即回退到 `DefaultWeightsProvider`。这是保证计算结果正确的最后一道防线。
