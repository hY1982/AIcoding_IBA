# Module 1.4 — 比赛意向实体（intentions + intention_venues + intention_formats）

## Context

根据 `basketball-match-platform-specs.md` 的分模块开发计划，Module 1.1（用户与认证实体）、1.2（场地实体）、1.3（赛制实体）已完成。Module 1.4 是 Phase 1（数据层）的第四个模块，负责定义比赛意向及关联实体，是后续匹配引擎（Module 2.6）和意向服务（Module 2.5）的数据基础。

本模块严格遵循 TDD 原则：先编写测试代码，再编写实现代码。测试覆盖率目标 80%+。

---

## 依赖关系

- **前置依赖**: Module 1.1 (`users`, `players`, `player_positions`) + Module 1.2 (`venues`) + Module 1.3 (`formats`)
- **后续依赖**: Module 1.5 (`matches`), Module 2.5 (`IntentionService`), Module 2.6 (`MatchingEngineService`)

## 数据库设计规范（来自 blueprint）

### `intentions` 表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGSERIAL | PK | 自增主键 |
| player_id | BIGINT | NOT NULL, FK → players(id) ON DELETE CASCADE | 提交意向的球员 |
| start_time | TIMESTAMPTZ | NOT NULL | 意向开始时间 |
| duration_minutes | INT | NOT NULL, CHECK 120-360 | 比赛时长（2-6小时） |
| acceptable_wait_minutes | INT | NOT NULL, DEFAULT 30 | 可接受等待时长（分钟），默认30分钟 |
| end_time | TIMESTAMPTZ | GENERATED STORED | 生成列：start_time + duration_minutes |
| status | VARCHAR(20) | NOT NULL, DEFAULT 'pending' | 枚举：pending/matched/confirmed/cancelled/expired/failed |
| match_id | BIGINT | nullable | 匹配成功后关联 |
| region_code | VARCHAR(20) | nullable | 分区键 |
| submitted_at | TIMESTAMPTZ | DEFAULT NOW() | 提交时间 |
| updated_at | TIMESTAMPTZ | DEFAULT NOW() | 更新时间 |
| expires_at | TIMESTAMPTZ | NOT NULL | 意向过期时间 |

**索引**:
- `idx_intentions_status` on (status)
- `idx_intentions_time` on (start_time, end_time)
- `idx_intentions_player` on (player_id, status)
- `idx_intentions_region_status_time` on (region_code, status, start_time) — 匹配任务核心索引

### `intention_venues` 表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGSERIAL | PK | 自增主键 |
| intention_id | BIGINT | NOT NULL, FK → intentions(id) ON DELETE CASCADE | 关联意向 |
| venue_id | BIGINT | NOT NULL, FK → venues(id) | 关联场地 |
| priority | INT | NOT NULL, DEFAULT 1 | 优先级 1=最高 |

**唯一约束**: (intention_id, venue_id)

### `intention_formats` 表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGSERIAL | PK | 自增主键 |
| intention_id | BIGINT | NOT NULL, FK → intentions(id) ON DELETE CASCADE | 关联意向 |
| format_id | BIGINT | NOT NULL, FK → formats(id) | 关联赛制 |
| priority | INT | NOT NULL, DEFAULT 1 | 优先级 1=最高 |

**唯一约束**: (intention_id, format_id)

### 步骤 3: 编写实体实现代码

#### 3.1 `intention.entity.ts`

TypeORM 实体设计要点：
- 使用 `@Entity('intentions')`
- `@Index` 装饰器定义所有索引
- `player_id` 列 + `@ManyToOne(() => Player)` + `@JoinColumn`
- `start_time`: `@Column({ type: 'timestamptz' })`
- `duration_minutes`: `@Column({ type: 'int' })` + `@Check` 约束
- `acceptable_wait_minutes`: `@Column({ type: 'int', default: 30 })` — 业务语义：用户愿意为匹配成功额外等待的最大分钟数，默认30分钟以提高匹配成功率
- `end_time`: `@Column({ type: 'timestamptz', generatedType: 'STORED', asExpression: "start_time + INTERVAL '1 minute' * duration_minutes" })`
- `status`: `@Column({ type: 'enum', enum: INTENTION_STATUSES, default: 'pending' })`
- `match_id`: `@Column({ type: 'bigint', nullable: true })`（暂不关联 Match 实体，Module 1.5 完成后补充外键。TODO: 在字段旁添加注释标记技术债务）
- `region_code`: `@Column({ type: 'varchar', length: 20, nullable: true })` — 填充策略：由后端根据 player_id 对应的用户地区，或 intention_venues 中优先级最高的场地地区自动计算并填充。Module 2.5（意向服务）中实现此逻辑
- `submitted_at`: `@CreateDateColumn({ name: 'submitted_at' })`
- `updated_at`: `@UpdateDateColumn({ name: 'updated_at' })`
- `expires_at`: `@Column({ type: 'timestamptz', nullable: false })` — 生成规则：submitted_at + acceptable_wait_minutes。在应用层（Module 2.5 意向服务或实体生命周期钩子）中强制保证，不可由用户直接设置
- 一对多关系：`intentionVenues`、`intentionFormats`

#### 3.2 `intention-venue.entity.ts`

- `@Entity('intention_venues')`
- `@Index(['intentionId', 'venueId'], { unique: true })`
- `intention_id` 列 + `@ManyToOne(() => Intention, { onDelete: 'CASCADE' })`
- `venue_id` 列 + `@ManyToOne(() => Venue)`（不级联删除 venue）
- `priority`: `@Column({ type: 'int', default: 1 })`

#### 3.3 `intention-format.entity.ts`

- `@Entity('intention_formats')`
- `@Index(['intentionId', 'formatId'], { unique: true })`
- `intention_id` 列 + `@ManyToOne(() => Intention, { onDelete: 'CASCADE' })`
- `format_id` 列 + `@ManyToOne(() => Format)`（不级联删除 format）
- `priority`: `@Column({ type: 'int', default: 1 })`

## 关键设计决策

1. **end_time 生成列**: 使用 PostgreSQL `GENERATED ALWAYS AS (start_time + INTERVAL '1 minute' * duration_minutes) STORED`，确保数据库层面自动维护，避免应用层不一致。

2. **match_id 暂不建立关系**: Module 1.5 才创建 `matches` 表，因此 `intentions.match_id` 仅作为普通 bigint 列，不定义 `@ManyToOne` 关系。Module 1.5 完成后可补充关系（或通过 Migration 添加外键）。

3. **级联删除策略**: `intention_venues` 和 `intention_formats` 对 `intentions` 使用 `ON DELETE CASCADE`；对 `venues` 和 `formats` 不使用级联删除（业务上场地/赛制删除应先清理关联意向，或阻止删除）。

4. **CHECK 约束**: `duration_minutes` 使用数据库 CHECK 约束 `CHK_intentions_duration` 限制 120-360。

5. **status 枚举**: 使用 TypeORM `enum` 类型 + PostgreSQL ENUM，与现有实体风格一致。

6. **expires_at 生成规则**: 在应用层（Module 2.5 意向服务或实体 `@BeforeInsert` 钩子）中强制计算：`expires_at = submitted_at + acceptable_wait_minutes`。不可由用户直接设置，确保业务正确性。

7. **region_code 填充策略**: 由后端自动计算，优先从 player_id 对应的用户地区获取，其次从 intention_venues 中优先级最高的场地地区获取。确保插入时不为空，满足匹配引擎依赖。

8. **match_id 技术债务**: 当前仅作为普通 bigint 列。Module 1.5 创建 matches 表后，需通过新 Migration 补充外键约束：`ALTER TABLE intentions ADD CONSTRAINT FK_intentions_match FOREIGN KEY (match_id) REFERENCES matches(id)`。
